# Blindspot report: seedance-motion-studio (pipeline with miora-video-studio and travel-skill)

Map: video 0.2.1    Profile: none    Date: 2026-11-17

## Scope
- Pipeline: seedance-motion-studio (brief to delivery handoff for Seedance 2.0 films: product, news, science, brand), miora-video-studio (submits and tracks generation jobs on the Miora/MiniMax H3 channel), travel-skill (travel promos from real and AI shots). Read in full: these three. The four prompt-only skills (action-fight-prompt, cinematic-asset-prompts, emotion-performance-director, travel-photo-to-video) were read at description level only.
- Delivers: briefs, claims register, treatment, shot cards, prompts, generation logs, QA report, edit plan and delivery package. It plans and compiles; it generates only through an environment-provided tool (miora).
- Ends at: a delivery package and handoff report. It does not shoot, upload, publish, or analyse results.
- Plainly not involved: live action filming, casting, account or channel management, monetisation.

## Findings

### Needed
None. Each candidate gap below has at least partial coverage in the skill folder or repository root, or lies outside the delivery boundary.

### Worth considering
1. **No handoff from the Seedance shot cards to the generation channel actually installed (miora runs MiniMax H3)** [model+trace]
   Map node: none — unsourced
   Why: grep `MiniMax`, `H3`, `WorkBuddy`, `768`, `resolution` on the skill folder and repo root: seedance-motion-studio never names miora or H3 (only IMPORT-NOTES.md says miora "仍保留在仓库中"). Its step 6 says "compile the prompt for the verified Seedance interface"; generic interface check exists (SKILL.md line 98), so this is partial. Miora needs mode, resolution, 4–15 s integer duration, aspect ratio and a 7000-character limit before submission, and has no dialogue input; shot-card fields do not carry mode or resolution, and the Seedance reference syntax is not mapped to H3.
   Fix: in seedance-motion-studio SKILL.md step 6/7, add a line saying what to do when the available channel is not Seedance (map shot card to the channel's required parameters and limits), and point to miora-video-studio for that case.
2. **AI-generated content disclosure to the platform is not a step** [map+model]
   Map node: comp.ai-disclosure, comp.media-law-ethics — source: see `sources` output for the video map
   Why: grep `AIGC`, `AI 标识`, `disclos`, `label`, `水印`, `watermark`: only a blank "Required label/disclosure:" in templates/research-dossier.md:35 and the news-explainer rule to label illustrative reconstructions. Nothing says to find the destination platform's AI label rule or put it in delivery-checklist.md.
   Fix: add to references/postproduction.md "交付规格" and templates/delivery-checklist.md a line to confirm the platform's AI-label requirement and record how it is met.
3. **Rights and clearance for references, music and likeness are listed but not checked** [map+model]
   Map node: pre.releases, assets.music-licensing, assets.rights-acquisition, assets.copyright-fair-use, assets.trademarks — source: see `sources` output
   Why: grep `licen`, `copyright`, `版权`, `release`, `consent`, `肖像`, `授权`: asset-manifest.csv has a `rights_or_privacy_notes` column, seedance-reference-mapping.md:34 asks about authorisation limits, delivery-checklist.md has "license notes", travel-skill failure-catalog.md:62-63 reminds about portrait and watermark risk. All are prompts to note, none say to verify before use or what to do if unclear.
   Fix: in references/seedance-reference-mapping.md and postproduction.md, add a check step that rights are confirmed (or the asset is replaced) before an asset is used as a reference or in the final cut.
4. **No screening of the finished film (or of what the model refuses) against platform content policy** [map+model]
   Map node: comp.community-guidelines, comp.minors, comp.medical-claims, comp.dangerous-content — source: see `sources` output
   Why: grep `moderation`, `审核`, `违规`, `safety`, `refus`, `拒绝`, `minor`: no match in the skill folder or code; only travel-skill's cultural and portrait reminders. Also no instruction for when the generation tool rejects a reference or prompt on policy grounds (miora handles errors, not moderation).
   Fix: add a content-policy line to references/quality-gates.md full-film QA, and a policy-rejection branch to the Iteration policy.
5. **Captions and accessibility are named but not made** [map+model]
   Map node: captions.transcription, captions.create, captions.edit, captions.translate, captions.accuracy-accessibility, captions.silent-viewing — source: see `sources` output
   Why: grep `字幕`, `caption`, `accessib`, `静音`, `silent`, `subtitle`: delivery-checklist.md lists "Subtitle file and narration script" and brief.md has "Languages/subtitles", but no step to produce or check them, and no sound-off check.
   Fix: in references/postproduction.md add how captions are produced and checked, and a sound-off viewing item in templates/qa-report.md.

   Map node: topic.audience-research — source: see `sources` output
   Why: brief.md has "Audience context/platform" but no instruction to look at what the audience searches or watches.
