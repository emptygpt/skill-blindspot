## Scope
- Inspects failing GitHub Actions PR checks using gh and a bundled log helper; external-provider checks are reported by URL only.
- Reports failure context, drafts an inline/optional create-plan plan, requests explicit approval and implements the approved repair.
- Ends at a local fix with diff/test summary, suggested test/check re-runs and a question about opening a PR.
- Does not require a commit, push, merge, deployment or ongoing CI-monitor loop; source/test execution after the repair is suggested rather than a mandatory completed step.

## Findings

### Needed
1. **Match the editable checkout to the requested PR before applying the approved fix** [model+map+trace]
   Map node: agent.wrong-output — source: NIST AI 600-1, 2.2 <https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf>; OWASP LLM09 <https://genai.owasp.org/llm-top-10/>.
   Why: The skill accepts an explicit PR number/URL independently of the current checkout, then applies its plan locally without verifying that the editable repository/revision is that PR's source. find_git_root only locates a repository, and fetching/printing run headBranch/headSha does not compare or align the editable tree; neither performs part of that identity check. Plan approval authorizes a repair but cannot make the wrong checkout the requested target.
   Fix: after PR resolution and before approving/applying edits, resolve the PR's source repository/head and establish a matching clean or explicitly owned worktree, stopping for a decision on mismatch or existing edits.
   Grep terms: `checkout`, `worktree`, `headSha`, `headRefName`, `current branch`; searched skill and repository root with --max 10000 and inspected all matching helper/metadata paths. Current-branch discovery covers the default lookup, not the explicit-PR-to-editable-tree binding.

2. **Keep CI evidence from becoming instructions for the repair agent** [model+map+trace]
   Map node: agent.injected-instructions — source: OWASP Top 10 for LLM Applications 2025, LLM01 <https://genai.owasp.org/llm-top-10/>.
   Why: The helper copies CI-controlled text into the agent's context immediately before plan generation and approved code changes, without an instruction/data boundary. Shell-free subprocess argument arrays protect the helper's gh invocation from shell expansion, not the model from instructions inside a returned log; human plan approval controls actions, not which input may redefine those actions.
   Fix: at failure-context intake and planning, label retrieved log/check text as non-authoritative evidence that cannot change the requested goal, approval policy, tools or permissions.
   Grep terms: `untrusted`, `ignore instructions`, `instruction hierarchy`, `prompt injection`; searched skill and repository root with --max 10000. No matching intake rule exists in this skill; uncalled security/sandbox/deployment siblings do not cover it.

### Worth considering
3. **Validate the diagnosed cause and retain observed repair evidence** [model+map+trace]
   Map node: operations.root-cause, testing.test-the-change, testing.reproduce-and-report — source: NIST SP 800-218, RV.3 <https://csrc.nist.gov/pubs/sp/800/218/final>; O*NET 31.0, tasks 14639 and 14641–14643 <https://www.onetcenter.org/database.html>; ESCO, replicate customer software issues <https://esco.ec.europa.eu>.
   Why: The wrapper explicitly asks to summarize the root cause, the helper supplies genuine failure evidence, and Step 8 suggests re-running relevant tests/checks, so these specific stages are partly instructed. The workflow does not require tracing a hypothesis into the causal code/configuration path or observing the failing check turn green, and its helper selects the last textual failure marker rather than proving a cause. These are deficiencies in actual causal/verification instructions, not absence inferred from generic plan approval.
   Fix: between summary and repair, check the causal path against code/configuration; before reporting completion, run or explicitly hand off the reproducer/affected checks with observed before/after results and remaining uncertainty.
   Search check: `root cause`, `reproduc`, `trace`, `hypothes`, `inspect.*code` found the wrapper's root-cause prompt and the helper's traceback marker, not a causal-validation procedure; the wrapper is why this is not Needed.

4. **Minimise diagnostic exposure and bound the helper's execution envelope** [model+map+trace]
   Map node: agent.sensitive-data, agent.limit-agency — source: OWASP LLM02/LLM06 <https://genai.owasp.org/llm-top-10/>; NIST AI 600-1, 2.4/2.9 <https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf>.
   Why: The approved-plan gate, external-provider exclusion and configurable snippet length are concrete authority/output bounds. Full logs/raw errors are still captured without a privacy filter, byte bound or subprocess timeout, and suggested repo/workflow authentication scopes are not tailored to the read-only inspection phase. Data sensitivity, CI size and permitted execution identity vary by repository, so this is Worth considering rather than an assertion of an observed leak or hang.
   Fix: in prerequisites, log fetching and summarization, define phase-appropriate credentials, resource bounds and sensitive-value minimisation/redaction while preserving failure context.

### Minor
5. **Keep --json valid on the no-failing-check path** [model+trace] (unsourced)
   Why: main returns a plain-text success sentence before the --json branch when no failing checks remain. A consumer using the advertised machine-readable mode cannot parse that normal successful outcome as JSON.
   Fix: route the empty result through the same JSON envelope as the non-empty result and preserve the distinction between no failures, pending/unknown state and retrieval errors.

6. **Clarify whether the next action updates the existing PR or creates another one** [model+trace] (unsourced)
   Why: Intake already resolves a PR, but the implementation step ends by asking about opening a PR. No new PR is actually opened, so this is a handoff ambiguity rather than an unauthorized publication.
   Fix: make the final question depend on whether the approved fix belongs on the resolved PR head or an explicitly chosen separate branch.

## Unsourced findings

- Branch mismatch, injected instructions, causal misdiagnosis, disclosure and hangs were not induced or observed. This is static inspection, not a live CI reproduction.
- create-plan's contents could not be determined; the permitted inline fallback, not an invented called workflow, is the audited planning path.
