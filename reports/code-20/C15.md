## Scope
- Coordinates one locally exercisable named bug/hypothesis: normalize claim/invariant and bounded repair plan, independently reproduce/validate, make a minimal local patch commit and independently prove it.
- Includes called reproduction, validation, patch, proof and regression-hunt workflows, receipt validation, variant/control cases and deterministic local HTML rendering.
- Ends at retained evidence, a local commit when present, an auditor report for reportable outcomes and a maintainer handoff only for a verified READY patch, with human next action.
- Does not push, open PRs/issues, merge, deploy to production or run a release/maintenance programme. Generic local patching does not import every security, UI, crypto or dependency-management node.

## Findings

### Needed
None. Independent execution, invariant/variant search, observed red/green tests, complete-tree revert, case controls, regression adjudication and conservative evidence-gap verdicts supply substantive safeguards.

### Worth considering
1. **Extend execution limits to every main proof build and PoC** [model+map+trace]
   Map node: agent.limit-agency, agent.generated-code-execution — source: OWASP LLM05/LLM06 <https://genai.owasp.org/llm-top-10/>; OWASP Agentic ASI02/ASI03/ASI05 <https://genai.owasp.org/2025/12/09/owasp-top-10-for-agentic-applications-the-benchmark-for-agentic-security-in-the-age-of-autonomous-ai/>.
   Why: Local scope, fresh agents, owned worktrees, a three-attempt cap and the called campaign's explicit permissions already limit agency. The main arms helper executes build/PoC argument arrays in worktrees under the caller's OS identity; filesystem separation and its per-command timeout alone do not state permitted network/data effects or protect authoritative receipts from a hostile tested process.
   Fix: in main preflight/proof handoffs, define the proof execution envelope and, for untrusted targets, isolate credentials/network/evidence and verify all spawned resources terminate.

2. **Treat PoC-source omission as narrower than safe disclosure** [model+map+trace]
   Map node: agent.sensitive-data — source: OWASP LLM02 <https://genai.owasp.org/llm-top-10/>; NIST AI 600-1, 2.4/2.9 <https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf>.
   Why: The skill requires a disclosure choice, the called contract forbids secrets/live credentials and the renderer can omit PoC/harness sources. Static inspection of collect_evidence/_display_record shows that raw receipts, planned inputs and some reproduction commands remain report content when include_poc is false; that choice is not a general sensitive-value redactor.
   Fix: before sharing, review all rendered values/commands/logs and create an authorized redacted derivative where necessary while retaining original private sealed evidence.

3. **Check whether the repair changes existing documentation** [model+map+trace]
   Map node: documentation.technical-docs — source: ESCO, provide technical documentation <https://esco.ec.europa.eu>; O*NET 31.0, task 21669 <https://www.onetcenter.org/database.html>; Google Engineering Practices, Documentation <https://google.github.io/eng-practices/>.
   Why: Detailed reports and reproducible test procedures document the repair, but the patch loop does not check whether existing API/error/configuration documentation became inaccurate. Many invariant-restoring fixes need no product-doc change, so this is conditional rather than a reason to expand the repair beyond its brief.
   Fix: in implement-patch's final review, check affected documentation or record that no update is required.

### Minor
4. **Keep the invariant rationale with the local commit** [model+map+trace]
   Map node: version-control.commit-messages — source: Conventional Commits 1.0.0 <https://www.conventionalcommits.org/en/v1.0.0/>; Google Engineering Practices, First Line/Body is Informative <https://google.github.io/eng-practices/>.
   Why: Commit and patch records retain identity, variants and suite outcomes, and the report explains why the fix works. There is no instruction for the commit message itself, so that intent may be lost when the local commit is reviewed outside the run directory.
   Fix: in implement-patch's commit step, require the repository's concise message convention plus the corrected invariant and reason.
