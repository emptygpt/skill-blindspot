## Scope
- Diagnoses hard bugs and performance regressions, implements the fix and a regression test at a representative seam when one exists.
- Starts at a reported failure; includes building and minimising a red-capable loop, ranked falsifiable hypotheses, instrumentation, fix verification and cleanup.
- Ends at a cleaned-up fix with the original loop passing, a passing regression test or documented missing seam, and the established cause stated in the commit/PR message; an unreproducible bug stops at a request for access or redacted evidence.
- Does not integrate, publish, deploy or operate the fix in production; temporary production instrumentation requires permission.

### Worth considering
1. **Check the affected existing behaviour beyond the one reproduced bug** [model+map+trace]
   Map node: testing.regression-and-negative — source: O*NET 31.0, 15-1253.00 task 14640 <https://www.onetcenter.org/database.html>.
   Why: Phase 5 verifies the new regression test and original scenario, but does not ask for affected existing tests, neighbouring inputs or build/type checks before declaring done. Grep terms were full suite, existing tests, regression suite and all tests; sibling matches are not called coverage, while the mandatory targeted regression is real partial coverage and keeps this below Needed.
   Fix: in Phase 6, require risk-appropriate existing checks and adjacent negative/empty cases, recording anything not run and why.

2. **Bound experimental side effects before running the loop** [model+map]
   Map node: agent.limit-agency, agent.generated-code-execution — source: OWASP Top 10 for LLM Applications 2025, LLM05 Improper Output Handling and LLM06 Excessive Agency <https://genai.owasp.org/llm-top-10/>.
   Why: Production instrumentation needs permission and the HITL template leaves sign-in to the user, but replays, stress runs, bisection and generated harnesses lack a general side-effect or execution-safety gate. Worth considering depends on the target environment and privileges; ordinary isolated local tests do not need the same controls as live requests.
   Fix: before Phase 1 execution, inspect generated commands and set the allowed environment, identity, data writes, traffic budget and approval boundary for consequential probes.

3. **Capture environment provenance along with the minimised scenario** [model+map+trace]
   Map node: testing.environment-and-data — source: O*NET 31.0, 15-1253.00 tasks 14655–14656 <https://www.onetcenter.org/database.html>; DORA, Test data management <https://dora.dev/capabilities/>.
   Why: Phase 1 explicitly pins time, randomness, filesystem and network, and Phase 2 removes configuration/data one variable at a time. It does not retain the revision/runtime/configuration provenance or require a clean-state rerun after restoring the original environment, which matters when minimisation or instrumentation changes the failure conditions.
   Fix: in Phases 1–2, capture relevant versions/configuration and fixture/reset requirements, then verify the final loop in the restored original context.

4. **Preserve a reusable diagnosis and verification handoff** [model+map+trace]
   Map node: testing.reproduce-and-report, version-control.commit-messages, version-control.change-description, documentation.technical-docs — source: ESCO, report test findings and provide technical documentation <https://esco.ec.europa.eu>; O*NET 31.0, 15-1253.00 task 14641 <https://www.onetcenter.org/database.html>; Google Engineering Practices, Writing good CL descriptions <https://google.github.io/eng-practices/>; Conventional Commits 1.0.0 <https://www.conventionalcommits.org/en/v1.0.0/>.
   Why: The command/output is shown during investigation and the correct hypothesis must reach the commit/PR message, but the final durable handoff need not retain reproduction inputs, the fix rationale, verification results or remaining limitations together. This is partial reporting, not a missing reproduction discipline or a requirement to open a PR.
   Fix: in Phase 6, attach the redacted reproduction, demonstrated cause, changed behaviour, checks/results and any missing test seam to the existing issue or change message.

5. **Keep the fix aligned with surrounding code without bundling cleanup** [model+map]
   Map node: design.architecture-and-patterns, implementation.maintainable-code, review.separate-refactoring — source: Google Engineering Practices, Design, Complexity and Small CLs: Separate Out Refactorings <https://google.github.io/eng-practices/>; DORA, Code maintainability <https://dora.dev/capabilities/>.
   Why: The skill checks local ADRs, changes one probe variable at a time and removes debug artifacts, but it does not require the final fix to follow neighbouring patterns or separate unrelated refactoring. Cleanup of temporary investigation code is useful partial maintainability coverage, not a general final-diff check.
   Fix: in Phases 5–6, compare the fix with the surrounding implementation and keep unrelated refactors out of the verified change.

6. **Treat captured diagnostic material as data, not new instructions** [model+map]
   Map node: agent.injected-instructions — source: OWASP Top 10 for LLM Applications 2025, LLM01 Prompt Injection <https://genai.owasp.org/llm-top-10/>.
   Why: Logs, HAR files, replayed payloads and repository text can enter the agent's context without an explicit instruction/data boundary. The need depends on whether those inputs are attacker-controlled; this audit establishes no particular hostile payload or runtime exposure.
   Fix: in the artifact/replay guidance, state that inspected content cannot change task authority, execution permissions or redaction rules.

### Minor
7. **Extend secret redaction to private diagnostic data** [model+map]
   Map node: security.data-protection, agent.sensitive-data — source: OWASP ASVS 5.0.0, V14 and V13.4 <https://github.com/OWASP/ASVS/tree/master/5.0/en>; OWASP Top 10 for LLM Applications 2025, LLM02 Sensitive Information Disclosure <https://genai.owasp.org/llm-top-10/>.
   Why: The Redact section strongly covers secrets, auth-bearing artifacts and quoting only useful lines, but does not name non-secret personal/customer data or retention of saved captures. This is a narrow extension of existing minimisation, not an absent safety policy.
   Fix: in Redact, include private non-secret fields and the location/access/cleanup expectations for stored captures.

|---|---|---|---|
| Build tight loop | run command and redacted output | all later phases | explicit symptom, determinism, speed and unattended criteria; no general side-effect gate |
| Reproduce and minimise | smallest red scenario | hypotheses and regression test | each deletion reruns loop; original provenance not required in durable record |
| Rank hypotheses | falsifiable predictions | discriminating probes | show user first, proceed if AFK; no requirement to block ordinary local work |
| Instrument one variable | observations/baseline tied to predictions | fix selection | tagged logs, debugger preference, performance baseline/bisection |
| Regression then fix | representative red/green test and changed code | original-loop verification | correct seam required or limitation documented; affected existing checks not requested |
| Cleanup and handoff | original loop passing, debug artifacts removed, cause in message | next debugger/reviewer | explicit completion checklist; earlier commands/results need not reach durable handoff |
