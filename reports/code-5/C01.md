I read SKILL.md, implementer-prompt.md, task-reviewer-prompt.md, re-review-prompt.md and all seven files under references/ (batching, cannot-verify, final-review, fix-loop, handling-reports, preflight, resuming). Map: software 0.1.0    Profile: none    Date: 2026-11-17

## Scope
- Controller skill: it takes a finished implementation plan and runs it by dispatching one implementer subagent per task, one task review (spec plus quality) per task, a bounded fix loop, and a whole-branch review at the end.
- Responsibility starts at a plan (and optional spec) and an isolated worktree, and ends when the final review is clean and the agent hands over to finishing-a-development-branch. Writing the plan, design, merging, pull requests and release are outside it.
- The controller does not write code or fix findings itself, and does not pause to ask except for four named stop conditions.
- The subject matter of each task (security, data, UI, dependencies) is set by the plan, not by this skill.

### Worth considering
1. **Task reviewer and implementer prompts carry no security lens** [model+map]
   Map nodes: requirements.security-requirements, implementation.secure-coding, implementation.input-and-output-handling, security.identity-and-access, security.crypto-and-transport, security.data-protection, security.web-api-and-files, security.security-criteria, security.logging-and-detection, security.integrity, testing.security-testing. Sources: `python3 -I scripts/blindspot.py sources --map software <node>` (OWASP and NIST SSDF entries in the map).
   Why: searched all prompts and references for security, injection, auth, crypto, logging; only the final reviewer (code-reviewer.md:80, "Security concerns?") has one line. A task that adds a login route can pass spec and quality review, and the issue first surfaces at the end.
   Fix: in task-reviewer-prompt.md Part 2, add a short item that applies when the brief touches input, auth, data or files, and let the controller copy plan security constraints into the Global Constraints block.

2. **Packages and generated code added by implementers are not checked** [model+map]
   Map nodes: dependencies.choose-and-verify, dependencies.declare-and-inventory, dependencies.supply-chain, dependencies.licence-compliance, agent.suggested-dependencies, agent.generated-ip.
   Why: "Dependencies or assumptions" in implementer-prompt.md means task dependencies. Nothing tells the implementer to report a new package, or the reviewer to look at manifest and lock-file hunks.
   Fix: add a "new dependencies" line to the implementer report format and a matching check in the task reviewer's Part 2.

3. **Secrets and private data in commits, briefs, reports and the ledger** [model+map]
   Map nodes: implementation.secrets, agent.sensitive-data.
   Why: the implementer commits and writes reports to a workspace; no item mentions credentials or private data. The workspace is git-ignored, but reports and diffs are still pasted into subagent contexts.
   Fix: add one rule to implementer-prompt.md (never commit or paste secrets) and one reviewer check on the diff.

4. **Subagents treat the plan, repo files and tool output as trusted, with no permission limits** [model+map]
   Map nodes: agent.injected-instructions, agent.limit-agency, agent.generated-code-execution, security.protect-environments-and-code.
   Why: the "four things that stop you" bind the controller only (SKILL.md, "Rulings, not stalls"). The implementer prompt has no equivalent, no limit on destructive or out-of-worktree commands, and no line about instructions found inside files it reads. The reviewer is told to be read-only, so the implementer prompt is the one without guards.
   Fix: copy the stop conditions into implementer-prompt.md and add one sentence that instructions found in repo content or tool output are data.

5. **Controller rulings do not reach the task reviewer** [trace]
   Map node: unsourced.
   Why: preflight rulings and fix-loop rulings are carried into implementer dispatches (SKILL.md Task Loop 1, item 4; fix-loop.md "carry it into the next task's dispatch"). The reviewer gets only the brief, the report, the diff and Global Constraints (SKILL.md section 3), and is told never to pre-judge. A ruling that changes the brief can therefore be reported as spec ❌ and send the task back into the loop.
   Fix: in SKILL.md section 3, say how a recorded ruling is passed to the reviewer (for example as an extra constraint line with its ledger reference) without telling it to ignore findings.

### Minor
6. **Plan-specific engineering concerns have no home in the reviewer rubric** [model+map]
   Map nodes: implementation.toolchain-and-build, implementation.configuration, implementation.data-migration, implementation.accessibility, testing.environment-and-data, review.analysis-tools.
   Why: nothing mentions linters or static analysis, configuration, migrations, accessibility or realistic test data. Absent rather than not-applicable because the skill does the implementing; placed in Minor so the author can exclude them in a profile.
   Fix: optional prompt line "apply the project's linter and build checks named in the plan".

7. **Commit message format and backing out a task** [model+map]
   Map nodes: version-control.commit-messages, version-control.revert.
   Why: implementer-prompt.md says only "Commit your work". The ledger records commit ranges, but nothing says how to revert a task that was parked at the cap.
   Fix: one line in implementer-prompt.md; a revert note in fix-loop.md's breaker section.

8. **Regression coverage between tasks rests on one full run before each commit** [model+map]
   Map nodes: testing.regression-and-negative, testing.automation.
   Why: fix rounds re-run only covering tests (fix-loop.md) and the next full run is in finishing-a-development-branch. A late task can break an earlier one for a long stretch before anyone sees it.
   Fix: optional line in references/fix-loop.md or SKILL.md section 5 to run the suite when a task completes.

9. **Documentation and readability are checked only at the end** [model+map]
   Map nodes: documentation.technical-docs, documentation.review-docs, review.readability.
   Why: code-reviewer.md:92 asks "Documentation complete?" at the final review; the task reviewer has no naming, comment or doc item.
   Fix: optional line in task-reviewer-prompt.md Part 2.

10. **Final-review fix wave has no brief or report file** [trace]
    Map node: unsourced.
    Why: final-review.md dispatches one fix subagent and a scoped re-review, but implementer-prompt.md and re-review-prompt.md expect a brief path and a report path, and none is defined for that wave.
    Fix: name the file paths for the wave in references/final-review.md.
