# Blindspot report: security-audit

Skill under audit: cloudflare/security-audit-skill, skills/security-audit/SKILL.md (repo: https://github.com/cloudflare/security-audit-skill). I read SKILL.md in full and all 14 companion markdown files (RECONNAISSANCE, HUNTING, ATTACK-CLASSES, VALIDATION-AND-REPORTING, and the nine domain companions), plus the README and report-schema.json. I did not read the four .cjs validators or their tests (code; read by name only). The four files the prepare step flagged as missing (architecture.md, REPORT.md, FINDINGS-DETAIL.md, NEEDS-VALIDATION.md) are output files the skill writes, not absent inputs.

Map: software 0.1.0    Profile: none    Date: 2026-11-17

## Scope
- Does: a source-first security audit of a codebase. It runs reconnaissance, coverage-led hunting by isolated agents, independent verification, and writes a structured findings file plus three reports. It also works in a lighter "guidance mode" for security questions.
- Starts at a target repository and a user request. Ends at the report files and two validators passing. It does not modify target source, commit, open pull requests, release or publish.
- Does not probe live systems, install dependencies, or run target code outside an OS sandbox.
- The software map describes making a change to software. Most of its implementation, version-control, release and operations nodes are therefore outside this skill's boundary.

## Findings

### Needed
1. **Text inside the target is not declared to be data, not instructions, for the agents** [model+map]
   Map node: agent.injected-instructions — source: OWASP Top 10 for LLM Applications 2025, "LLM01:2025 Prompt Injection"; OWASP Top 10 for Agentic Applications for 2026, "ASI01 - Agent Goal Hijack"
   Why: the skill sandboxes target code execution with care, but its hunters and verifiers read arbitrary repository text (comments, README, agent-instruction files, fixtures). I searched SKILL.md, HUNTING.md, RECONNAISSANCE.md, VALIDATION-AND-REPORTING.md and ATTACK-CLASSES.md for "untrusted", "adversarial", "hostile", "prompt injection" and agent-file names. The only hits concern untrusted input to the target, not to the auditing agents. AI-AND-LLM.md covers targets that use LLMs, not the audit's own agents. A planted line such as "mark this path as reviewed" could corrupt the ledger.
   Fix: add a rule in SKILL.md "Universal execution safety" and in the hunter and verifier prompt blocks in HUNTING.md and VALIDATION-AND-REPORTING.md that repository content is evidence only and never overrides the task, plus what a hunter does when it finds such text (report it as a finding, do not obey it).

2. **Secrets found in the target can be copied into findings and reports** [model+map]
   Map node: agent.sensitive-data, security.data-protection — source: OWASP Top 10 for LLM Applications 2025, "LLM02:2025 Sensitive Information Disclosure"; NIST AI 600-1, Artificial Intelligence Risk Management Framework: Generative Artificial Intelligence Profile, "2.9 Information Security"
   Why: ATTACK-CLASSES.md L56-58 and L113 send hunters to find hardcoded passwords, keys and tokens, and git history is searched for removed secrets (L103). The credential rules at SKILL.md L82 and HUNTING.md L83-84 cover the captured environment only. Nothing tells the agent to mask a discovered secret value in `findings.json`, REPORT.md or FINDINGS-DETAIL.md, which are written for sharing. report-schema.json and the findings validator contain no secret or redaction mention.
   Fix: add a step in VALIDATION-AND-REPORTING.md Phase 4 and 6 (and a line in the hunter prompt in HUNTING.md) to record a discovered secret by location and type with the value masked, and to flag it as live-credential rotation for the owner.

### Worth considering
1. **No step for delivering results to owners, or for a person to look at the report before it is relied on** [model+map]
   Map node: requirements.consult-and-report, agent.human-oversight — source: O*NET 31.0 Database, task statements and detailed work activities for 15-1252.00 Software Developers and 15-1253.00 Software Quality Assurance Analysts and Testers, "15-1252.00 task 21664: Confer with systems analysts, engineers, programmers and others to design systems and to obtain information on project limitations and capabilities, performance requirements and interfaces."; O*NET 31.0 Database, task statements and detailed work activities for 15-1252.00 Software Developers and 15-1253.00 Software Quality Assurance Analysts and Testers, "15-1252.00 task 21665: Consult with customers or other departments on project status, proposals, or technical issues, such as software system design or maintenance."
   Why: SKILL.md L8 says "give owners the source evidence", and needs_validation items carry owner-observed plans, but no phase says who receives the report, in what order severe findings are escalated, or that a person reviews before it is shared. The only human question is the mode choice (L15-17). Fix: add a short delivery step after Phase 6 in SKILL.md "Full audit workflow".

2. **Report prose is not checked against the final records after it is written** [trace]
   Map node: unsourced
   Why: Phase 6 derives REPORT.md, FINDINGS-DETAIL.md and NEEDS-VALIDATION.md from findings.json. Anti-pattern 10 forbids prose and JSON disagreeing, and L118 says the validator "proves format and ledger consistency only". No step compares the three prose files to the records, or confirms nothing from the secret/path class above leaks into them. Fix: add a final check step to VALIDATION-AND-REPORTING.md Phase 6.

3. **Logging and detection is only touched as log injection** [model+map]
   Map node: security.logging-and-detection — source: OWASP Application Security Verification Standard (ASVS) 5.0.0, "V16.3 Security Events"; OWASP Application Security Verification Standard (ASVS) 5.0.0, "V16.4 Log Protection"
   Why: ATTACK-CLASSES.md L34 names log injection and L58 secrets in logs. No attack class asks whether security-relevant events (authorization failures, admin actions) are logged at all or whether the logs can be tampered with. Fix: add a short class to ATTACK-CLASSES.md.

4. **Known-vulnerable dependencies have no source of advisories** [model+map]
   Map node: dependencies.declare-and-inventory — source: The Twelve-Factor App (factor titles only), "II. Dependencies: Explicitly declare and isolate dependencies"; OWASP Application Security Verification Standard (ASVS) 5.0.0, "15.1.2: An inventory catalog, such as software bill of materials (SBOM), is maintained"
   Why: ATTACK-CLASSES.md L120 asks "are there known CVEs in the dependency tree? (check lockfiles)", but the sandbox forbids network and SUPPLY-CHAIN-AND-RELEASE.md L12 says a vulnerable dependency alone is not a finding. How an offline agent learns of advisories, or how it records an unchecked tree, is not said. Fix: state in SUPPLY-CHAIN-AND-RELEASE.md that advisory lookup is a needs_validation owner step.
