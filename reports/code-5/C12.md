# Blindspot report: git-workflow-and-versioning
Skill under audit: addyosmani/agent-skills, skills/git-workflow-and-versioning/SKILL.md (https://github.com/addyosmani/agent-skills). I read the whole of SKILL.md (355 lines, the only file in the skill folder) and searched the repository root, including the sibling skills it cites, for anything covering a gap before rating it Needed.

Map: software 0.1.0    Profile: none    Date: 2026-11-17

## Scope
- Git workflow discipline for an AI coding agent (atomic commits, branches, worktrees, save points, pre-commit hygiene) plus the versioning contract (semver, tags, changelog). It delivers commits, change summaries, tags and changelog entries.
- Starts at any code change and ends at a tagged release with a changelog entry. Deploying and launch belong to shipping-and-launch, CI to ci-cd-and-automation, review content to code-review-and-quality.
- Does not involve requirements, design, writing the code itself, runtime operation or vulnerability handling.

## Findings

### Needed
1. **Merge conflict resolution and integration are promised but missing** [model+map+trace]
   Map node: version-control.integrate-and-merge — source: GitHub Docs, "Pull requests documentation: Resolve merge conflicts" <https://docs.github.com/en/pull-requests>; GitHub Docs, "Troubleshoot status checks"
   Why: the description lists "resolving conflicts" as a trigger, but a search of the body for conflict, rebase, merge and status checks finds only "merge within 1-3 days". The repo has no other file covering it (only an eval prompt "Resolve the merge conflict").
   Fix: add a section under Branching Strategy that says how to sync with main, resolve and verify a conflict (tests after resolving, never blindly pick one side), and when to rebase versus merge.

2. **No procedure for splitting a messy working tree into atomic commits** [model+trace] (unsourced)
   Why: the description names "splitting uncommitted work in a messy working tree into clean atomic commits", yet "Atomic Commits" only shows good and bad log examples. Searched for add -p, stash, staging, partial: nothing.
   Fix: in "Atomic Commits", add the steps for grouping hunks, staging selectively, and checking each commit builds on its own.

3. **Destructive git operations and the agent's authority to commit, push and tag are unguarded** [model+map+trace]
   Map node: agent.limit-agency, version-control.revert, agent.human-oversight — source: OWASP Top 10 for LLM Applications 2025, "LLM06:2025 Excessive Agency" <https://genai.owasp.org/llm-top-10/>; GitHub Docs, "Revert a pull request"
   Why: "The Save Point Pattern" tells the agent "git reset --hard HEAD takes you back", which also discards uncommitted work and the failing diff it is about to "Investigate". Force-pushing appears only as a Red Flag, with no safe form and no rule on when the agent must ask before pushing, tagging or deleting branches. There is no git revert for commits already pushed.
   Fix: in "The Save Point Pattern" and Red Flags, add a guard (check status or stash before reset), the pushed-history alternative, and which git actions need the user's go-ahead.

### Worth considering
4. **Pull request opening and description** [model+map] — nodes review.pull-request, version-control.change-description, review.handle-comments, review.owners-and-approval. Source: Google Engineering Practices, "Writing good CL descriptions"; GitHub Docs, "Draft pull requests"; GitHub Docs, "About code owners: CODEOWNERS and branch protection". The description promises PR handling but "Change Summaries" is a reply format, not PR text. Nothing on responding to comments or branch protection (ci-cd-and-automation mentions protection, but this skill does not point to it). Fix: add a short PR subsection (description of what and why, draft, review responses, required checks).
5. **Bad release recovery and release integrity** [model+map] — nodes maintenance.bad-release, release.archive-and-integrity. Source: Semantic Versioning 2.0.0, FAQ on accidentally releasing an incompatible change; NIST SP 800-218 PS.2 and PS.3. Tags are called immutable, but nothing says what to do when a tagged release is wrong or how a tag is made verifiable. Fix: in "Tag the release", add retract-by-new-patch guidance and signed tags.
6. **Secret leak remediation** [model+map] — node implementation.secrets. Source: GitHub Docs, "Secret scanning: Push protection"; OWASP ASVS 5.0.0 V13.3. The secret scan in Pre-Commit Hygiene is manual and the hooks example is lint-only. security-and-hardening says rotate first then purge, but this skill does not link to it. Fix: in "Pre-Commit Hygiene", add a push-time secret block and the rotate-then-purge step or a pointer.
7. **No Unreleased changelog convention** [trace] — the skill says write the entry "in the same change", but its example entry carries a version and date that are unknown at that moment. Fix: in "Keep a changelog", add an Unreleased heading that is renamed at tagging.
8. **Merge strategy is unstated** [model] (unsourced) — squash, rebase or merge commit is never chosen, while a rationalization row says "Squashing destroys the development narrative". Fix: state the default strategy and its effect on atomic history.

### Minor
9. **Static analysis findings are not recorded or triaged** [map] — node review.analysis-tools. Source: NIST SP 800-218 PW.7. Lint and tsc run before commit but results are not tracked. Fix: one line in Pre-Commit Hygiene.
10. **Lockfile is the only dependency record** [map] — node dependencies.declare-and-inventory. Source: The Twelve-Factor App, II Dependencies. Only "commit package-lock.json" is said. Fix: one line in "Handling Generated Files" that lockfile changes get reviewed.
11. **Breaking-change marker, commit signing, large files** [model] (unsourced) — no BREAKING CHANGE footer in the commit format, no signing, no LFS or large-file rule.
