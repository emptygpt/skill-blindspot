# skill-blindspot

**找出你的 Agent Skill 自己不知道缺了什么。**

[English](README.md) | 中文

格式检查工具看的是写法。实测评估看的是 Skill 在你想到的任务上能不能跑通。这两样都不会告诉你：有一个环节你从头就没想到。

`skill-blindspot` 拿一张**领域底图**去对照一个 Agent Skill（含 `SKILL.md` 的文件夹）。底图来自人已经整理好的知识：职业任务数据库、教材和课程目录、平台官方文档。它报告你的 Skill 覆盖了领域里的哪些部分、哪些只是提了一句、哪些完全没有。每一条都带出处。

> **状态：早期。** 这个仓库公开开发。第一个领域是视频制作。目前还不能安装使用，进度见下面的路线图。

## 为什么做

写 Skill 的时候，你和模型都在最初的框架里工作。模型会把已有的部分打磨好，但很少提醒你整个环节缺失。一个视频 Skill 可以把写脚本这一步做得很细，却没有「确认素材使用权」这一步。

直接问模型「缺什么」，答案来自模型自己的先验，没有出处，两次结果也无法比较。领域底图是一个文本文件，懂行的人可以审阅、改正，可以记录版本、比较差异。

## 怎么工作

1. **领域底图。** 一棵 YAML 树，列出一个领域的环节和要点。每个节点有编号、上级、来源、链接和许可。没有来源的节点不许进底图。模型可以合并同义项、调整粗细，不能添加知识。
2. **对照。** 对每个节点，工具在 Skill 里找证据，并引用找到的原文行。每个节点得到四种状态之一：已覆盖、很浅、没有、故意不做。
3. **个人档案。** 缺口不是都要补。不适用于你的条目，写进一个小的档案文件，理由可写可不写，下次检查会照办。公共底图对所有人相同，个人档案只记你自己的情况。

「公共目录加个人档案」的分法在其他行业有成熟先例，例如 NIST 网络安全框架的档案机制，以及 OSCAL 的目录和档案。

## 它不做什么

- 不给 Skill 打分，不评价好坏。
- 不替你生成缺失的部分。
- 不代替在真实任务上运行 Skill。

## 路线图

- [ ] 验证：带出处的底图，能不能找回被删掉的环节，而直接问「缺什么」找不回？结果无论好坏都会公布在这里。
- [ ] `maps/video.yaml`：第一张领域底图，每个节点都有来源
- [ ] `blindspot` 命令行工具：输入 Skill 文件夹和底图，输出 Markdown 和 JSON 报告
- [ ] 报告：公开的视频 Skill 最常缺哪些环节
- [ ] 第二个领域（写作），以及给新领域做底图的指南

## 相关工作

- [SkillFoundry](https://github.com/ma-compbio-lab/SkillFoundry) 用领域树决定给一个库造哪些 Skill。本项目是拿底图审一个已有的 Skill。
- [NVIDIA SkillEvaluator](https://github.com/NVIDIA/SkillEvaluator) 做校验、去重和实测评估，不检查领域覆盖。

## 参与

最有价值的贡献是领域知识：补一个带来源的节点，或者改正一个已有节点。第一张底图发布时会写明格式。
